## Verdict: **continue**

Nothing in ADR 0028's table triggers a stop or a re-scope. The data supports the plan: migrations
of this kind are mostly unchanged code (83% to 100% congruent), between 17% and 73% of the changed pairs
lower with no opaque (37% on Git Extensions), and nothing behaviour-changing that was seeded was called Equivalent.

Things the run found that the table does not measure, in the order they matter:

1. **Verification crashes on 92 of the 1,200 Git Extensions pairs that were not congruent and so
   reached the solver (7.7%), and on the same shapes in two smaller pairs.** 47 are one bug, a
   derived class against its base (P2-031), and 34 are another, nullable annotations on array types
   (P2-032). Together they account for 81 of the 92.
2. **`--execute` hung for hours on one pair (P2-039)**, so a corpus run with `--execute` cannot be
   assumed to finish.
3. **Execution found 54 real differences the solver could not decide on Git Extensions** (Unknown to
   Divergent, `proofMethod: observed`), 9 of them in production code, which is the strongest
   evidence in this run that the second oracle earns its cost.
4. **16 Divergent results did not reproduce on the real runtimes** (P2-037, P2-038). 15 are
   runtime-change results the replay cannot observe by design; 1 is a solver Divergent
   (`GitSshHelpers::SetSsh`) where the model and the CLR disagree.
5. The mechanical seeder crashes on the two larger pairs (P2-035), so mechanical recall rests on 23
   seeds from two small pairs.
6. Results with solver timeouts are not exactly repeatable: two results changed rule between the
   plain and `--execute` runs of the same inputs.

Criterion 5 of the ticket (three most and three least believable Divergent results) is in the Git
Extensions summary. The user delegated the choice, so they are the agent's picks, grounded in the
replay evidence.
