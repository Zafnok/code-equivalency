# IOperation lowering coverage

Maintained by the Frontend.CSharp tickets. One row per `OperationKind`. Status:
`lowered` (with test name), `opaque` (falls back to `IrOpaque`), `n/a` (never appears
in a CFG body). Every kind found in `samples/` must have a row
(`SampleLoweringTests.EveryOperationKindInTheSamplesHasACoverageRow`).

Shared fragments (ADR 0024 decision 2; M4-004): every `opaque` row says whether its fragment can be shared. An
expression-level opaque, including every fallback a `lowered` row names, is shared when the same bound fingerprint
occurs on both sides of a pair: both occurrences are then one call `opaque:<fingerprint>` over the variables the
fragment reads, with a `threw` edge to `System.Exception` and the heap pairs a call has. It gets no fingerprint, and
stays opaque, when it is not an expression, holds a flow capture, null test or caught exception of the graph or a
struct's `this`, writes a local or parameter declared outside it, calls a local function declared outside it, reads a
`ref` local, holds a lambda capturing a variable that is assigned after it or that any lambda or local function writes,
or is runtime-sensitive (M3-015). A whole-body opaque is never shared; congruence covers an unchanged body (ADR 0024
decision 1). A runtime-sensitive conversion to a delegate is not shared either, but it still lowers, as a function each
side has of its own (row `DelegateCreation`; P2-136).

A struct that inherits a generic interface's code (ADR 0024, clarified 2026-10-12 (P2-161)): whatever a row says, an
operation whose type is, or is made of (an array's element, a type argument), a struct whose interface list hands a
generic interface of the solution a type with a layout is opaque with reason `Layout`, on `Invocation`'s terms, where
it brings the value into the body. That leaves out a constant (null), an assignment and a step, which yield the value
they store, and a flow capture that holds a value. The fragment's fingerprint holds the declaration of every type the
interface list hands over (P2-157), and `Layouts` is the one rule both read. An operation that names any other struct
is lowered as its row says (`IrLowererTests.AnOperationThatNamesAStructWithNoGenericInterfaceIsLoweredAsItWas`). The
rows `ParameterReference`, `LocalReference`, `FieldReference` and `ArrayElementReference` say so themselves, being the
reads that bring in a value no operation of the body made. A reference that hands a member of the solution a class
whose interface list hands such a type over is the opaque the rows `Invocation`, `ObjectCreation`, `FieldReference` and
`PropertyReference` make of one that hands over a type with a layout (P2-154; P2-162;
`IrLowererTests.AReferenceThatHandsAMemberAClassIsAnOpaqueWhereItsInterfaceListHandsOverATypeWithALayout`).
